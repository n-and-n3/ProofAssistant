# ProofAssistant

命題論理のシークエント計算（$Γ \vdash Δ$）を、推論規則の合成として記述して実行するミニDSL（`.n3`）です。
このREADMEは「実装の説明」よりも、この言語を実際に書けるようになるための最短リファレンスを意図しています。

## クイックスタート

ビルド:

- `g++ main.cpp -o main`

実行（proofファイルを1つ渡す）:

- `./main ./proofs/De_Morgan.n3`
- `./main ./proofs/impimp.n3`

Pythonで証明を自動生成:

- `python3 main.py` : `|- A->A` の証明を標準出力へ生成
- `python3 main.py 'A->B, B->C, ~C |- ~A'` : 指定したシークエントの証明を生成
- `python3 main.py > ./proofs/auto_iff.n3`
- `./main ./proofs/auto_iff.n3`

Pythonの標準出力は、そのまま保存して実行できる `.n3` だけです。構文エラーや証明不能のメッセージは標準エラーへ出力され、終了コードは非0になります。生成される最後の証明宣言には `[期待シークエント]` が付き、C++実行時にも目標との完全一致を検証します。

サニタイザ付き（開発用）:

- `g++ -g -O0 -fsanitize=address,undefined -fno-omit-frame-pointer main.cpp -o main_asan && ./main_asan ./proofs/impimp.n3`

## 言語の基本

### 1. 文（statement）

すべての文は `;` で終わります（改行は単なる空白扱い）。

- 型宣言: `Type A;`
- 証明（検証つき）: `[期待シークエント] name = proof;`
- 証明（検証なし）: `auto name = proof;`
- 表示: `print name;`

`[ ... ]` つき宣言は、`proof` の評価結果が **期待シークエントと一致するか**を実行時にチェックします。

### 2. 命題（Prop）

命題変数は `Type` で宣言した識別子のみ使えます。

- 変数: `A`
- 否定: `~A`
- 連言: `A*B`
- 選言: `A+B`
- 含意: `A->B`
- 括弧: `(A->(B*C))` など（※制限は後述）

演算子優先順位（強い→弱い）:

- `~` > `*` > `+` > `->`

### 3. シークエント（Sequent）

書式:

- `Γ |- Δ`

左（Γ）・右（Δ）は `,` 区切りで命題を並べます。内部表現は集合なので:

- 順序は意味に影響しません
- 重複は自動的に潰れます
- 表示順は `unordered_set` の都合で安定しません

空側も書けます:

- `|- A`
- `A |-`

### 4. 証明式（proof expression）

推論規則呼び出しをネストして書きます:

- `rule<テンプレート引数...>(前提シークエント...)`

前提シークエントは

- 既に束縛したシークエント変数（`auto s = ...;` など）
- もしくは明示的なシークエント `A,B |- C`（※制限は後述）

のどちらでも渡せます。

## 推論規則チートシート

テンプレート引数は命題（Prop）、丸括弧は前提シークエント（Sequent）です。

### 基本・弱化

- `Id<P>()` : `P |- P`
- `KL<A>(Γ |- Δ)` : `A, Γ |- Δ`
- `KR<A>(Γ |- Δ)` : `Γ |- Δ, A`

### 否定

- `notL<A>(Γ |- Δ, A)` : `~A, Γ |- Δ`
- `notR<A>(A, Γ |- Δ)` : `Γ |- Δ, ~A`

### 連言

- `andL<A,B>(A, B, Γ |- Δ)` : `A*B, Γ |- Δ`
- `andR<A,B>(Γ |- Δ, A ,  Γ |- Δ, B)` : `Γ |- Δ, A*B`

### 選言

- `orL<A,B>(A, Γ |- Δ ,  B, Γ |- Δ)` : `A+B, Γ |- Δ`
- `orR<A,B>(Γ |- Δ, A, B)` : `Γ |- Δ, A+B`

### 含意

- `impL<A,B>(Γ |- Δ, A ,  B, Γ |- Δ)` : `A->B, Γ |- Δ`
- `impR<A,B>(A, Γ |- Δ, B)` : `Γ |- Δ, A->B`

## 例（proofs/）

- [proofs/De_Morgan.n3](proofs/De_Morgan.n3): `~(A*B) |- ~A + ~B`
- [proofs/impimp.n3](proofs/impimp.n3): `A->B, B->C, ~C |- ~A`
- [proofs/very_complex.n3](proofs/very_complex.n3): `((A->B)*(B->C)), ((C->D)*(~D)) |- ~A`

## 既知の制限・コツ（重要）

- **コメント構文はありません**（`//` などを書くと構文エラーになります）
- `proof expression` は内部的に `)` をトリガとして解釈しているため、
	- `rule<...>` の **テンプレート引数内に括弧 `(` `)` を含める**
	- `rule(... )` の **引数として明示シークエントを直接書いて、その中の命題に括弧を含める**
	などは壊れやすいです。
	- 回避策: 先に `[ ... ] name = ...;` や `auto name = ...;` で中間シークエントに名前を付けてから、引数は **変数名だけ**を渡してください。
- エラーは基本的に `runtime_error` で落ちます（`expected '|-'` / `unknown token` / 推論前提不成立など）
